# 📄 InsightPDF: Chat with Any PDF using RAG

Upload one or more PDFs and ask questions about them in plain English. InsightPDF finds the most relevant passages, hands them to a local LLM, and answers with **page citations**, all running on your own machine. No API keys, no cloud, and your documents never leave your computer.

## Features

- **Chat with your documents**: a Streamlit chat interface with conversation history.
- **Multiple PDFs**: upload several files at once and ask across all of them.
- **Cited answers**: every fact is tagged with its page number, e.g. `(page 3)`.
- **Transparent retrieval**: a "Sources used" panel under each answer shows the exact passages and similarity scores behind it.
- **Grounded responses**: the model is instructed to answer only from the retrieved text, and to say *"I couldn't find that in the document."* when the answer isn't there.
- **Fully local**: embeddings via `sentence-transformers`, vectors stored in ChromaDB on disk, answers generated by an [Ollama](https://ollama.com) model.
- **Streaming output**: answers appear word by word as they are generated.

## How it works

```
PDF ─► extract text ─► chunk (150 words, 30 overlap) ─► embed ─► ChromaDB
                                                                    │
Question ─► embed ─► top-4 most similar chunks ◄────────────────────┘
                              │
                              ▼
              prompt (rules + passages + question) ─► Ollama LLM ─► streamed answer
```

1. **Load**: `pypdf` extracts text page by page, keeping page numbers.
2. **Chunk**: each page is split into overlapping 150-word chunks so ideas aren't cut off at boundaries.
3. **Embed**: `all-MiniLM-L6-v2` turns each chunk into a 384-dimension vector.
4. **Store**: vectors, text and metadata (source file, page) are saved in a persistent ChromaDB collection using cosine similarity.
5. **Retrieve**: the question is embedded the same way and the 4 closest chunks are fetched.
6. **Generate**: the chunks and question are sent to a local LLM with instructions to stay within the context and cite pages.

## Tech stack

| Component | Choice |
|---|---|
| UI | [Streamlit](https://streamlit.io) |
| PDF parsing | [pypdf](https://pypdf.readthedocs.io) |
| Embeddings | [sentence-transformers](https://www.sbert.net) · `all-MiniLM-L6-v2` |
| Vector database | [ChromaDB](https://www.trychroma.com) (persistent, cosine similarity) |
| LLM | [Ollama](https://ollama.com) · `llama3.2:3b` by default |

## Getting started

### Prerequisites

- Python 3.10 or newer
- [Ollama](https://ollama.com/download) installed and running

### Installation

```bash
# 1. Clone the repository and enter the project folder
git clone https://github.com/<your-username>/InsightPDF-Chat-with-Any-PDF-using-RAG-.git
cd InsightPDF-Chat-with-Any-PDF-using-RAG-/"RAG CHATBOT"

# 2. (Recommended) create a virtual environment
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Download the LLM used for answering
ollama pull llama3.2:3b
```

The embedding model (`all-MiniLM-L6-v2`) is downloaded automatically the first time you index a PDF, so that first run takes a little longer.

### Run the app

Make sure Ollama is running, then from the `RAG CHATBOT` folder:

```bash
streamlit run app.py
```

Open the local URL Streamlit prints (usually http://localhost:8501), then:

1. Upload one or more PDFs in the sidebar and wait for "Indexed N chunks".
2. Ask a question in the chat box.
3. Expand **Sources used** to see which pages the answer came from.

> Run the commands from inside the `RAG CHATBOT` folder. The vector database folder (`chroma_db`) is created relative to where you launch the app.

### Quick test without the UI

`test_rag.py` runs the full pipeline in the terminal against the bundled `sample.pdf`:

```bash
python test_rag.py
```

## Configuration

All settings live at the top of [`rag.py`](RAG%20CHATBOT/rag.py):

| Setting | Default | What it does |
|---|---|---|
| `EMBEDDING_MODEL` | `sentence-transformers/all-MiniLM-L6-v2` | Model used to embed chunks and questions |
| `LLM_MODEL` | `llama3.2:3b` | Ollama model that writes the answer (must be pulled first) |
| `CHUNK_SIZE` | `150` | Words per chunk |
| `CHUNK_OVERLAP` | `30` | Words shared between neighbouring chunks |
| `TOP_K` | `4` | Number of chunks retrieved per question |
| `DB_DIR` | `chroma_db` | Where ChromaDB stores its data |

To use a different LLM, pull it (`ollama pull mistral`, for example) and set `LLM_MODEL = "mistral"`. Larger models usually give better answers; larger chunks or a higher `TOP_K` give the model more context at the cost of speed.

## Troubleshooting

- **"No text found in this PDF"**: the PDF is probably a scan (images of text). InsightPDF reads embedded text only and has no OCR. Run the file through an OCR tool first (for example `ocrmypdf`) and upload the result.
- **Connection or "model not found" errors from Ollama**: check that Ollama is running and that you have pulled the model named in `LLM_MODEL` (`ollama list` shows what's installed).
- **Slow first answer**: the embedding model is loading and Ollama is warming up the LLM. Later questions are faster.
- **Uploading new files replaces the old ones**: the index is rebuilt each time the set of uploaded files changes, and the chat history is cleared.

## Limitations

- Text-only: tables, images and scanned pages aren't interpreted.
- Answer quality depends on the local model you choose; small models can miss details or paraphrase loosely.
- Only one document set is indexed at a time.
